## 写报告时如何用图和数据

- **设计思路**写清个人要验证的业务规则、输入和预期。**实现过程**写工具版本、选取的数据、关键操作和实际观察。**系统应用**解释结论影响哪项业务，以及本次测试覆盖的范围。
- 引用小组记录时注明工具、构建或日期、用例号或请求名。把本人的复测结果另列一行。尚未执行的场景填写“尚未执行”，并说明缺少的条件。[共用数据的来源和统计口径](共用数据/README.md)
- **尽量减少重复，尤其是图片。** 优先截本人验证对象的断言、状态变化或方法覆盖明细。同一观察点选一张最清楚的图即可。多个数字适合放在同一张表里。引用同一张团队图片时标明来源、图号和用途。
- 例如 C 验证重复生成任务，可用两行表格列出同一工单操作前后的任务 ID 和数量。这个对照比一张任务列表总览更能回答问题。仓库保留一张 [JaCoCo 原生页面示例](示例图/JaCoCo服务包覆盖页.png)，用于辨认列名。图中 Total 是整个服务实现包，六个核心服务的合计请使用第二章的覆盖计数表。
- 在本地提交给老师的副本中填写姓名、学号和班级。共享截图请裁去个人资料、账号、登录响应及会话值。

项目代码按 [后端](项目源码/backend/)、[Web 前端](项目源码/frontend/)和[小程序](项目源码/miniprogram/)保存。需要复测时，按[源码与本地环境说明](项目源码/README.md)准备独立实验库和测试数据。
