# 开发规范

## 1. 项目边界

| 层 | 路径 | 固定约定 |
| --- | --- | --- |
| 后端 | `backend` | Spring Boot 3.5.11、Java 17、MyBatis、MySQL、Redis、Shiro Core、Log4j2 |
| 前端 | `frontend` | Vue 3 + Vue Router + Vite，按登录角色展示不同业务视图 |

| 文档 | `../docs/development` | 只维护契约、规范、验收冻结说明、演示稿和请求示例 |

## 5. 后端开发规则

1. 新增资源时补齐 `entity`、`controller`、`service`、`service/impl`、`repository`、`resources/mapper`。
2. Controller 路径使用 `@RequestMapping({"/resource", "/api/resource"})`，前端只调用 `/api/resource`。
3. 通用 CRUD 保持 `list`、`add`、`/{id}`、`PUT /{id}`、`POST /update`、`DELETE /{id}`。
4. 接口统一返回 `com.keyboard.mes.dto.Result`，字段为 `code`、`msg`、`data`。
5. Java 和 JSON 字段使用 lowerCamelCase；数据库字段使用 snake_case。
6. MyBatis XML 字段必须与实体、`schema.sql`、前端 `domain.js` 同步。
7. 涉及报工、质检、返修、状态流转的业务接口必须使用事务。
8. 必要中文注释只写在复杂业务规则、状态流转和非显然 SQL 处。
9. 日志统一使用 SLF4J API，由 Log4j2 输出；不得直接使用 `System.out.println`。
10. 未预期异常必须交给 `GlobalExceptionHandler` 记录完整堆栈。
11. 表结构写入 `schema.sql`，完整演示数据写入 `reset_rich_mock_data.sql`；SQL 目录只保留建表脚本和当前演示数据脚本，避免维护多套互相冲突的数据源。

## 6. 前端开发规则

1. 入口固定为 `frontend/index.html`。
2. Vue 入口位于 `frontend/src/app.js`。
3. API 封装位于 `frontend/src/api.js`。
4. 模块、字段、字典、外键关系位于 `frontend/src/domain.js`。
5. 页面导航使用 Vue Router，路由需与岗位权限同步。
6. 请求默认使用 `DEFAULT_API_BASE = 'http://localhost:8088/api'`。
7. `fetch` 必须带 `credentials: 'include'`。
8. 前端判断业务成功以 `result.code === 200` 为准。
9. 前端角色视图只负责体验，后端必须在 `AuthInterceptor` 或 Controller 层做权限兜底。

## 7. 登录会话规则

| 项 | 约定 |
| --- | --- |
| 登录 | `POST /api/auth/login` |
| 当前用户 | `GET /api/auth/current` |
| 退出 | `POST /api/auth/logout` |
| Cookie | `MES_SESSION_ID` |
| Redis key | `keyboard_mes:login:{sessionId}` |
| 调试请求头 | `Authorization: {sessionId}` 或 `Authorization: Bearer {sessionId}` |
| 密码字段 | 请求用 `password`，用户表保存 `password_hash` / API 字段 `passwordHash` |

## 8. 变更同步清单

| 变更类型 | 必须同步 |
| --- | --- |
| 新增/修改字段 | `entity`、Mapper XML、`schema.sql`、`frontend/src/domain.js`、`API接口文档.md`、`接口请求示例.http` |
| 新增业务资源 | Controller、Service、Mapper、SQL、前端模块、API 文档、测试 |
| 新增业务动作接口 | Controller、Service、必要事务、`API接口文档.md`、`接口请求示例.http`、前端调用 |
| 修改状态枚举 | `schema.sql` 注释、`frontend/src/domain.js` 字典、API 文档 |
| 修改登录/权限 | `AuthController`、`AuthSessionService`、`AuthInterceptor`、前端登录逻辑、开发规范 |

## 9. 小程序开发规则

1. 小程序目录固定为 `miniprogram`。
2. 小程序不得直连数据库，只调用后端 `/api` 接口。
3. 小程序接口鉴权复用现有登录态或后续新增移动端 token，不得绕过后端鉴权。
4. 小程序首期做轻量能力：登录、生产看板、简单报表、扫码/输入 SN 追溯、轻量报工、轻量质检、轻量返修处理。
5. 小程序字段、状态、字典必须复用 `../docs/development/API接口文档.md` 和 `frontend/src/domain.js` 中的约定。
6. 后端接口发生变更时，必须同步 `API接口文档.md`、`项目验收与功能冻结说明.md` 和 `接口请求示例.http`。
7. 小程序现场处理只做轻量表单提交，不替代 Web 端完整业务流和审批流。

## 10. AI 开发执行规则

1. 修改前先阅读 `../docs/development/README.md` 指定的文档顺序。
2. 不得删除契约文档；只能更新为更准确的契约。
3. 不得把说明性长文写回 docs；新增内容必须是规则、契约、任务或请求示例。
4. 不得自行引入新框架、新目录、新接口风格；确需引入时先更新 `开发规范.md`。
5. 完成开发后至少执行 `git diff --check`；后端改动还要执行或说明未执行 `mvn test`。
