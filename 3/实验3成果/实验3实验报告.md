# 实验3 键盘MES后端单元测试实验报告

课程：软件测试与质量保证  
测试对象：Keyboard MES 后端  
执行日期：2026年9月29日

## 1 实验目标与范围

课程上机安排要求使用 JUnit 设计单元测试，对调用关系较复杂的程序单元结合 Mockito 测试，设计满足语句覆盖、分支覆盖和基本路径覆盖的用例，并使用 JaCoCo 统计覆盖率。本实验以 `program/code/backend` 中的 Spring Boot 后端为对象，重点检查工单生成、任务状态、报工、质检、返修复检和 SN 追溯服务。实验1的 MA-05 质量需求提出核心服务语句覆盖率不低于85%、分支覆盖率不低于80%，作为本次补测的目标。

本次测试基于 Git 提交 `e7a4522` 加当前未提交的业务修复、JaCoCo 配置和测试源码。测试运行使用 Mockito 模拟 Mapper 等依赖，不依赖正在运行的 MySQL、Redis 或前后端服务。

## 2 测试环境与方法

| 项目 | 本次配置 |
| --- | --- |
| Java 与构建 | JDK 17；Maven 3.9.9 |
| 测试框架 | `spring-boot-starter-test` 提供的 JUnit 5、Mockito 与 AssertJ |
| 覆盖率工具 | JaCoCo Maven 插件 0.8.12；Surefire 执行测试 |
| 执行方式 | 在 `program/code/backend` 执行 `mvn -o test`，依赖已缓存在本机 Maven 仓库 |
| 覆盖率报告 | `backend/target/site/jacoco/index.html`、`jacoco.csv`、`jacoco.xml` |

JaCoCo 执行数据写入系统临时目录的 `jacoco-mes.exec`。插件设置 `append=false`，使每次测试执行使用新数据，避免历史会话抬高覆盖率。下文统计取自本次单一测试会话生成的 Surefire XML 和 JaCoCo CSV。JaCoCo 提供代码行、分支和字节码指令覆盖率，没有直接名为“语句覆盖率”的指标；本报告用代码行覆盖率作为源代码语句覆盖的近似口径，并同时保留原始 CSV 供核查。同一源代码行若包含多条语句，这两个概念并不完全等同。

测试采用输入与预期结果断言，以及 Mockito 的依赖返回值和调用验证。业务用例覆盖正常操作、边界值、非法输入、依赖写入失败和关键状态转换。Controller 测试中的模拟 Service 不计入 Service 覆盖率。

## 3 白盒测试设计

### 3.1 基本路径分析

选取 `WorkReportServiceImpl.validateReportQuantity` 作为基本路径分析对象，通过 `submit` 调用该方法。设任务计划数为10、已完成数为4，则剩余可报工数为6。校验顺序依次为：D1 报工数不大于0；D2 合格数小于0；D3 不良数小于0；D4 合格数与不良数之和不等于报工数；D5 报工数大于剩余数。任一判断成立即拒绝，全部为假则接受。将短路表达式中的 D2、D3 分开计算后，5 个独立判断形成 6 条基本路径，环路复杂度 V(G)=6。

| 路径 | 报工数 / 合格数 / 不良数 | 首个成立判断 | 预期结果 | 对应用例 |
| --- | --- | --- | --- | --- |
| P1 | 0 / 0 / 0 | D1 | 拒绝非正报工数 | 数量校验测试第1组 |
| P2 | 2 / -1 / 3 | D2 | 拒绝负合格数 | 同上第2组 |
| P3 | 2 / 3 / -1 | D3 | 拒绝负不良数 | 同上第3组 |
| P4 | 2 / 1 / 0 | D4 | 拒绝数量不守恒 | 同上第4组 |
| P5 | 7 / 7 / 0 | D5 | 拒绝超过剩余数6 | 同上第5组 |
| P6 | 6 / 5 / 1 | 无 | 接受报工，累计完成数变为10 | 合法报工测试 |

P1 至 P5 均由 `submitShouldRejectQuantityBoundaryAndConservationViolations` 的对应输入组执行，各触发一条前述路径未经过的拒绝边；P6 由 `submitExactRemainingWithoutQualityGateShouldCompleteTaskAndOrder` 执行，穿过全部校验并进入保存和状态更新。上述六组输入均有业务结果断言，拒绝路径还验证报工记录未写入。任务完工、质检和返修复检另以状态转换及异常用例检查关键分支。

### 3.2 核心业务用例

| 对象 | 本次检查的关键行为 |
| --- | --- |
| 工单与任务 | 启用路线生成任务、重复生成保护、任务未达计划拒绝完工、质量门进入待质检、缺失路线处理 |

## 5 结论与范围限制

JUnit、Mockito 和 JaCoCo 的实验流程已完成，六个核心服务按本报告约定的代码行与分支口径均达到 MA-05 目标，选定校验方法的六条独立基本路径均有对应输入与结果断言。本轮未发现新的测试失败。

覆盖率结论限于本次运行的后端代码及六个核心服务。`ReportServiceImpl` 的代码行覆盖率为164/361（45.4%）、分支覆盖率为56/154（36.4%）；`ProductBomServiceImpl`、`ProcessRouteServiceImpl` 和 `SysUserServiceImpl` 仍无单元测试覆盖。这些类不计入上表六类合计。当前源码和测试尚有未提交改动，提交或复现实验前需以同一代码状态重新运行测试。
