# 实验3：单元测试方案

## 1. 实验目标

以 Keyboard MES 后端为对象，使用 JUnit 编写单元测试，使用 Mockito 隔离外部依赖，并用 JaCoCo 检查覆盖情况。重点练习语句覆盖、分支覆盖和基本路径测试，形成可复现的测试代码与覆盖率记录。

课程要求来源：整体上机课程安排第4页“上机3：单元测试”。实验1质量需求 MA-05 另提出核心服务语句覆盖率不低于85%、分支覆盖率不低于80%，并覆盖已识别的关键状态转换。

## 2. 测试对象与范围

项目目录为 `program`，后端 Maven 工程位于 `program/code/backend`。实验以现有后端代码和测试为基础，不把 Web、小程序或完整系统测试纳入本次单元测试统计。

优先检查和补充以下核心服务：

| 优先对象 | 重点场景 |
| --- | --- |
| `ProductionOrderServiceImpl`、`ProductionTaskServiceImpl` | 工单生成、工艺路线匹配、任务数量与状态流转、重复操作 |
| `WorkReportServiceImpl` | 合法报工、数量边界、合格与不良数量校验、超量拒绝 |
| `InspectionRecordServiceImpl`、`ReworkOrderServiceImpl` | 检验结论、返修与复检流程、状态限制及异常情况 |
| `TraceServiceImpl` | SN 查询、关联记录范围、无效或不存在的 SN |

上述服务已有对应测试类。实施时先运行并阅读现有测试，再确定缺口；不重复编写已有且有效的用例。

## 3. 测试方法

1. **JUnit**：按业务方法组织测试，覆盖正常输入、边界输入、非法输入和异常路径。
2. **Mockito**：模拟 Mapper、Redis 或其他外部依赖，预设返回值或异常，并验证关键依赖是否按预期调用；避免模拟被测服务自身。
3. **白盒覆盖**：针对选定的关键方法梳理条件判断和控制流，记录语句、分支及独立基本路径对应的输入。基本路径覆盖聚焦所选方法的独立路径，不宣称穷尽所有输入组合。
4. **状态转换**：对工单、任务、质检、返修和复检的关键状态，分别验证允许的转换及应被拒绝的转换。
5. **JaCoCo**：生成覆盖率报告，重点查看上述核心服务的行/指令覆盖和分支覆盖，并保留报告作为证据。

## 4. 实施步骤

1. 在 IDEA 中打开 `program/code/backend/pom.xml`，确认 JDK 17、Maven 配置和现有测试依赖；检查 `src/test/java` 下相关测试类及当前工程状态。
2. 选定核心服务和需补充的关键场景，建立“被测方法—测试输入—预期结果—覆盖目标”清单。
3. 先执行现有测试并记录基线结果，再编写或完善 JUnit/Mockito 测试。
4. 使用后端 `pom.xml` 中已配置的 JaCoCo 0.8.12 与 Surefire 运行测试；执行数据写入系统临时目录，`append=false` 确保新一轮报告不混入历史会话。
5. 执行测试、查看覆盖报告；针对未覆盖的关键分支或状态转换补充用例，再重新生成报告。
6. 整理测试结果和证据，区分通过、失败和未覆盖项，不把计划指标或历史数字写成实测结果。
