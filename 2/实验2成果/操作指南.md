本指南配合系统测试计划、76项测试条目和TestLink导入文件使用。命令按当前Windows电脑的实际路径准备。TestLink项目、需求、用例、测试计划和构建已建立；MES隔离环境已初始化并用于测试。实验2结果为59 PASS / 0 FAIL / 17 BLOCKED；76/76项均有状态记录，但仅59项完成PASS/FAIL判定，执行完成率和总通过率均为77.6%，未达到测试计划v1.0的整体退出门槛。详情见[系统测试报告](系统测试报告.docx)。服务状态会变化，启动前需按本指南重新检查。

更新日期：2026年9月22日。

## 5 准备隔离MES数据库

此步骤用于真实执行MES用例；只做TestLink计划管理时，可先完成第4节。不要在已有keyboard_mes库上执行演示重置SQL，它包含TRUNCATE，会清空数据。

已准备的脚本只创建新的keyboard_mes_lab2库；库已经存在时立即停止，不导入、不清空。每次调用MySQL会交互询问密码，密码不写入脚本。使用本机MySQL实际账号，默认root：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\commands\Initialize-LabDatabase.ps1' -DatabaseUser root
```

该脚本依次执行建表和演示数据初始化。若第二或第三阶段失败，保留新库并检查错误，不盲目重跑重置SQL。执行前后在phpMyAdmin确认数据库名；预期出现10张业务表。

也可以在MySQL交互终端检查：

```powershell
& 'C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe' --protocol=TCP --host=127.0.0.1 --port=3306 --user=root --password --database=keyboard_mes_lab2
```

在出现mysql>提示符后执行SQL，而不是粘贴到PowerShell：

```sql
SELECT DATABASE();
SHOW TABLES;
SELECT employee_no, role_code, status FROM sys_user;
SELECT COUNT(*) AS orders_count FROM production_order;
```

演示数据日期为2026年7月，而当前为9月，当前周月报表可能为空。报表用例需另建当前测试周期的隔离数据，或者在可控测试环境中固定时钟；不要据此直接判定报表缺陷，也不要直接修改全电脑系统时间。

## 6 启动Redis和MES

### Redis

先检查已有服务：

```powershell

& 'D:\Redis-x64-5.0.14.1\redis-cli.exe' -h 127.0.0.1 -p 6379 -n 15 DBSIZE
```

## 7 执行首条用例并记录

先执行KMES-F001有效账号登录。正常登录后查看当前用户；再按用例执行错误密码、退出和越权等检查。可使用以下命令核对API，密码交互输入，不输出会话凭据：

```powershell
$mesCredential = Get-Credential -UserName 'U001' -Message '输入隔离MES演示账号密码'
$loginBody = @{ employeeNo = $mesCredential.UserName; password = $mesCredential.GetNetworkCredential().Password } | ConvertTo-Json
$login = Invoke-RestMethod -Method Post -Uri 'http://localhost:8088/api/auth/login' -ContentType 'application/json' -Body $loginBody
if ($login.code -ne 200 -or -not $login.data.sessionId) { throw '登录失败，请检查服务与账号。' }
$headers = @{ Authorization = 'Bearer ' + $login.data.sessionId }
Invoke-RestMethod -Uri 'http://localhost:8088/api/auth/current' -Headers $headers
Invoke-RestMethod -Method Post -Uri 'http://localhost:8088/api/auth/logout' -Headers $headers
# 以下请求预期被拒绝：若HTTP返回401，PowerShell可能抛异常；记录HTTP及业务码。
Invoke-RestMethod -Uri 'http://localhost:8088/api/auth/current' -Headers $headers
Remove-Variable loginBody,login,headers,mesCredential -ErrorAction SilentlyContinue
```

按系统测试用例.md逐条执行后，在TestLink选择真实状态：符合全部预期为通过，产品不符合预期为失败，环境/前置数据无法满足为阻塞，没有尝试过为尚未执行。失败和阻塞必须附实际原因，不能为显示漂亮统计而全部标通过。

若仅完成登录相关场景，报告只写这些场景的结果。性能、可用性、用户调研、真机等专项未执行时保留未执行，不用单次接口成功替代专项验收。

## 11 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 点击Apache Admin进入dashboard | 正常；直接打开http://localhost:8080/testlink-lab2/ |
| 浏览器无法连接8080 | 查看Apache是否运行，再运行第2节的环境检查；不要直接改端口或终止未知进程 |
| XAMPP MySQL报3306占用 | 保持该项停止，TestLink使用本机已有MySQL服务 |
| 新站点的install地址返回404 | 安装器已移出站点，属于预期；访问站点首页登录 |
| 旧testlink-1.9.0出现PHP错误 | 使用testlink-lab2新地址，不继续操作旧安装器 |
| 登录提示账号或密码错误 | 核对本机账号文件；TestLink账号与MySQL、MES账号不同 |
| 出现邮件配置提示或无法邮件找回密码 | 尚未配置SMTP；核心项目管理可用，邮件功能暂不可用 |
| 数据库初始化提示库已存在 | 不删除数据库；先检查是否已初始化或上次仅完成部分导入 |
| 导入数量不符或需求没有关联 | 保留导入结果，检查XML和追踪矩阵；不要连续重复导入 |

排查TestLink错误时，可读取日志末尾，注意区分历史错误和刚刚发生的错误：

```powershell
Get-Content -LiteralPath 'D:\XAMPP\apache\logs\error.log' -Tail 40
Get-ChildItem -LiteralPath 'D:\XAMPP\testlink-data\logs' |
    Sort-Object LastWriteTime -Descending |
    Select-Object Name, LastWriteTime, Length
```
