# 实验5 接口测试实验报告

课程：软件测试与质量保证    小组：第22组

测试对象：Keyboard MES后端    实验日期：2026年10月7日

## 1 实验目的与测试范围

依据课程上机5安排，本实验使用Postman集合组织接口测试，通过其官方命令行执行器Newman运行。业务测试覆盖工单、生产任务和生产报表三类服务，并补充登录、退出及异常状态验证。最终执行10个请求、20项断言，全部通过。

## 2 环境与测试设计

测试复用已有keyboard_mes_lab2隔离数据库，后端运行于本机8088端口。为避免影响共享缓存，本次使用独立Redis实例和端口16379。测试仅查询业务数据，并创建和结束测试登录会话，没有创建工单、报工或质检记录。

Postman集合采用v2.1格式，Newman版本为6.2.1。登录成功后提取会话标识，作为后续请求的Authorization值；工单列表返回的首个编号作为详情查询输入，避免固定依赖某个业务编号。账号和密码在执行时传入，共享集合中的默认值为空。

## 3 用例与结果

| 测试内容 | 主要验证点 | 结果 |
| --- | --- | --- |
| 健康检查与登录 | 服务状态、业务成功码、会话标识 | 通过 |
| 工单列表与详情 | 列表非空、关键字段、数量及详情编号一致 | 通过 |
| 生产任务列表 | 列表结构、工单关联和状态范围 | 通过 |
| 生产概览 | 报工数量及质量指标结构 | 通过 |
| 周质量报表 | 周期为week、趋势数据包含7天 | 通过 |
| 不存在的工单 | 业务错误码与空数据 | 通过 |
| 退出与退出后查询 | 退出成功、失效会话返回未登录状态 | 通过 |

验证同时检查HTTP状态和业务响应，避免仅凭HTTP 200判定通过。例如，不存在工单和退出后的会话查询都以HTTP 200返回，但业务码分别为500和401，断言按接口实际契约判断。

首次执行时，质量趋势断言误用了trend字段。核对接口实现后改为trendData，并检查其长度为7；这是测试脚本修正，没有作为系统缺陷登记。修正后重新执行完整集合，最终10个请求、20项断言均通过，失败数为0。

## 4 结果分析与总结

本次验证表明，在现有隔离库数据和管理员测试会话下，三类业务查询及所测会话操作符合预期。集合已具备动态编号提取、变量传递和业务断言，后续可在Postman导入后继续补充。实际结果来自Newman运行，未记录Postman图形界面手工操作。

测试范围限于本次查询和会话场景，尚未覆盖业务写入、所有角色权限和全部接口组合，不能据此判断整个系统测试通过。下一步可围绕工单状态变化和不同角色增加独立用例，并保留相应数据清理安排。
