## 三处容易误读的记录

- **重复生成任务**。F014 的团队状态为 PASS，原始执行行只记了列表总数。个人验证应核对同一个工单在重复生成前后的任务标识和数量。已有单元测试覆盖返回已存在任务并避免重复写入的行为，名称是 `generateTasksShouldReturnExistingTasksWithoutDuplicating`。
- **质量门与报工数量**。F026 的设计用例描述尝试绕过质量约束，执行明细记录的是开启质量门后完工进入待质检。F018 的设计用了剩余量两侧的边界值，修复回归另用了超量 150 的样本。引用时写清采用哪条记录。
- **单元测试的适用范围**。工单数量至少为 1 由实体字段约束和控制器的参数校验实现。针对数量 0 的测试可从校验器或 HTTP 控制器入口发起，并核对写入未发生。原有测试类的通过总数不能证明这一新增场景或未授权场景已单独执行。

负载运行使用 1 线程每线程 10 次循环和 10 线程每线程 20 次循环。每次循环执行三项业务查询。吞吐量按整个场景的起止时间计算，包含等待时间。十用户场景的均值较低可能受缓存预热影响，结果只适用于该次短时运行。原始导出 JMX 的 HTTP 成功与补充 JMX 的业务断言在回放表中分行展示。
